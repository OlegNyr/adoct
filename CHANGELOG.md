## [1.4.0]

MCP: создание pull request'а в Bitbucket.

- **`bitbucket_create_pull_request`** — до сих пор Bitbucket-тулы умели только читать PR. Нужны
  репозиторий, исходная ветка и заголовок; целевая ветка по умолчанию — дефолтная ветка

- Тулов MCP теперь 76 (11 Bitbucket).

## [1.3.0]

Скорость выгрузки: пространство, которое раньше висело ~20 минут на «предобработке», теперь
проходит её за десятки секунд.

- **Пул соединений.** Раньше каждый REST-запрос поднимал новый HTTP-клиент и новое TLS-соединение;
  на тысячах запросов это и было основной статьёй расходов. Теперь клиент один на всю выгрузку.
- **Дерево страниц одним пакетом.** Пред-проход строил карту дерева запросом на каждую страницу.
  Для пространства оно забирается пагинированной выборкой (`expand=ancestors,version`) — десятки
  запросов вместо тысяч. При ошибке — откат на прежний обход по одной странице.
- **Инкрементальная выгрузка стала дешёвой.** Версия страницы известна из пред-прохода, поэтому у
  неизменившейся не запрашивается ни тело, ни rendered view, ни вложения.
- **Вложения — только свои.** Использовался эндпоинт вложений *всего поддерева*: файл с листа
  скачивался в `attache/` каждого предка, а пагинация шла по 25. Теперь запрашиваются вложения
  самой страницы пачками по 200.
- **Метки** едут в основном запросе (`expand=metadata.labels`) — минус запрос на страницу.
- **Кэш резолва ссылок** на весь прогон (пользователи и поиск страниц, включая отрицательный
  результат): один и тот же автор больше не резолвится сотни раз.
- **Параллельная выгрузка.** Страницы и вложения выгружаются одновременно. Степень задаётся
  в панели экспорта («Страниц параллельно», по умолчанию 4; `1` — прежнее последовательное
  поведение). Отмена и ошибка дожидаются уже запущенных страниц, чтобы не оставлять на диске
  файлы, дописанные после сообщения об отмене.
- **Прогресс на пред-проходе** — раньше он молчал, и выгрузка выглядела зависшей.

Новая настройка выгрузки:

- **«Только вложения, на которые ссылается страница»** (по умолчанию выключено). Скачиваются
  только файлы, на которые тело страницы реально ссылается; вложения, оставшиеся от прошлых
  версий, пропускаются, а `attache/` очищается перед загрузкой. Учитываются картинки, ссылки на
  файлы, макросы вне реестра (`view-file`, `multimedia`, `gallery`) и все варианты файлов drawio.
  Тот же параметр (`onlyUsedAttachments`) есть у MCP-тула `confluence_export_tree_to_adoc`.

Исправления:

- «Test Connection» в настройках сообщал об успехе ровно при неудачной проверке токена.
- Сбой скачивания вложения (5xx, ошибка записи) больше не проглатывается: раньше экспорт мог
  завершиться «успешно», оставив в `.adoc` ссылку на несуществующий файл.
- MCP-сервер не оставляет пулы соединений и потоки после перезапуска (смены настроек).
- Публикация на Windows падала (`InvalidPathException`), если в тексте упомянут шаблон пути вроде
  `` `stories/client-*.adoc` `` или картинка задана URL. Строка, которая не годится как путь, теперь
  остаётся на странице как есть.
- Ссылка с подписью, перенесённой на новую строку (`<<file.adoc#id,рабочее⏎место>>`), уходила
  в Confluence мёртвым `<a href="file.adoc#id">` вместо ссылки на страницу.

## [1.2.2]

Ссылки и картинки в выгрузке: круг замкнут — то, что видно на странице Confluence, работает и в файлах.

- Ссылки на страницы выгрузки резолвятся локально не только по заголовку, но и по `pageId` —
  «сырой» `<a href=…pageId=NNN>`, «человеческий» `/display/SPACE/Page+Title` и резолв `ac:link`
  через rendered view приводятся к пути на `index.adoc`/`index.md` (новый `LocalPages`).
- Ссылки, которые Confluence отдаёт относительными от хоста, достраиваются до абсолютных URL.
- Картинки, вставленные с другой страницы (`<ri:attachment><ri:page …/>`), докачиваются в `attache/`:
  URL берётся из rendered view, раньше такая ссылка вела в никуда.
- Экспорт не падает на ненайденной странице и на нескачавшемся вложении (нет прав, удалено) —
  предупреждение в лог, ссылка остаётся нерезолвленной.
- Нерезолвленная ссылка подписывается заголовком/именем файла вместо `toString()` записи.
- Пробелы и квадратные скобки в целях ссылок кодируются процентами (`link:` и markdown) — иначе
  ссылка на файл или папку с пробелом в имени не распознавалась как ссылка.
- Публикация: пути с `%20` декодируются при поиске файла — картинки и вложения с пробелом
  в имени снова находятся.

## [1.2.0]

Экспорт из Confluence в Markdown (GFM) наравне с AsciiDoc + улучшения выгрузки дерева.

- Второй формат экспорта — Markdown (GFM): выбор формата в IDEA-плагине и MCP-туле (`format`).
  Форматонезависимый AST, отдельный `MarkdownWriter` (alert-цитаты, HTML-фолбэк таблиц с
  colspan/rowspan/rich-ячейками, inline-HTML для подчёркивания/цвета).
- Перекрёстные ссылки между страницами выгружаемого дерева — локальные относительные пути на
  `index.adoc`/`index.md` (round-trip с публикацией), в т.ч. между разными корнями пространства.
- Выгрузка пространства целиком (`generateSpace`; чекбокс в IDEA, параметр `spaceKey` в MCP).
- Инкрементальная выгрузка: не изменившиеся страницы (по `version.when`) пропускаются.
- Макрос `children` → список локальных ссылок на дочерние страницы.
- Гэп-фичи в обоих форматах: списки-задачи, эмотиконы, подписи к картинкам, метки → `:keywords:`/`tags`,
  Page Properties (`details`).
- Расширенные метаданные в заголовке/frontmatter: url, space, author, created, version.
